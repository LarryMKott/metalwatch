## 落地 D35：开发 / 生产环境分离（METALWATCH_ENV）

**需求**：加一个全局环境变量区分开发与生产，且开发环境在两个 module 的 main 处无参数直接可运行。

**做法**：

- 新增 `backend/pkg/env`（纯标准库）：`METALWATCH_ENV` = `dev` / `prod`；判定顺序为
  「显式取值 > 存在 `TRIM_PKGVAR` 即 prod > 默认 dev」；非法取值**直接报错不回退**。
  Agent 经既有 `replace` 复用该包，不新增依赖。
- `config.Default()` 的 `DataDir` 由 `"./data"` 改为**空字符串**（内置默认不该猜数据落哪）：
  dev 由 main 补 `tmp-data`，prod 缺失即启动失败。
- dev 默认值全部落在各自 main：自动拾取 `configs/app.yaml`、数据 `tmp-data`、
  监听 `127.0.0.1`、日志同时进终端、打印开发横幅。
  判定「是否显式传参」用 `flag.Visit`，不要比较 flag 默认值（巧合相等时会误判）。
- 新增 `agent/internal/agentcfg`：`ResolveSpoolDir` / `ResolveServer` / `ResolveIdentity`
  + 凭据 `Store`（`credentials.json` 0600，含 token/host_id/server，兼容旧 `token` + `host_id.txt`）。
  dev 下自动读本地凭据 → 注册一次后无参数启动；**prod 刻意不读本地文件**（要显式注入）。
- `report.NewReporter` 的 hostID 改为构造参数注入（原来自读环境变量，会把凭据文件里的 host_id 丢掉）；
  `report.Client.Enroll` 补返回 hostID（JSON 通道此前丢弃，两条通道行为不一致）。
- FPK `cmd/main` 显式 `export METALWATCH_ENV=prod`（不依赖兜底判定，排障一眼可见）。
- `.gitignore` 补 `bin-local/`（内含 Agent 凭据，务必忽略）、`streamprobe.exe`、
  `deploy/script/package-lock.json`。

**验证**：两 module `go test -count=1 ./...` 全绿；无参数 migrate 输出 `env=dev data_dir=tmp-data`；
无参数 serve 打印横幅且 2 秒内 `/healthz` 就绪；未注册 Agent 给出清晰指引；check_fpk 22 项通过。
