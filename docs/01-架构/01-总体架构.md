# 01 · 总体架构

## 1. 定位与能力清单

面向多机房、跨网段物理服务器集群的硬件级监控、遥测与管控平台。

| # | 能力 | 实现要点 |
| --- | --- | --- |
| 1 | **硬件采集** | CPU / 内存 / 磁盘 / 网卡 / 电源 / 风扇全量资产与传感器指标。Linux 原生实现；Windows 走内嵌 C# NativeAOT 采集组件 |
| 2 | **双采集模式** | 带内 Agent + 带外 IPMI/BMC 轮询。操作系统宕机后仍可监控硬件状态 |
| 3 | **高实时通信** | Agent 与服务端 gRPC 双向流，秒级指标推送、指令实时下发 |
| 4 | **Mesh 最优路径转发** | Agent 可作中继，服务端集中 Dijkstra 计算最优路由，解决跨网段 / 出口带宽受限 |
| 5 | **BMC 硬件管控** | 远程风扇调速、电源控制、指示灯定位；手动 + 自动闭环策略 |
| 6 | **多存储可插拔** | 元数据与时序分层；默认 SQLite 开箱即用，支持外接 MySQL / PostgreSQL / GBase 8s、Prometheus / VictoriaMetrics / InfluxDB |
| 7 | **智能告警** | 硬件阈值、硬件变更检测、Agent 离线；支持分级、抑制、维护窗口 |
| 8 | **GeoIP 地域标签** | 内置 GeoIP / ASN 库，按节点 IP 自动打标，支持机房维度聚合 |
| 9 | **飞牛原生部署** | 标准 FPK 应用包，一键安装升级，复用飞牛的权限、日志、网络、持久卷能力 |

## 2. 技术栈总览

| 层级 | 选型 | 说明 |
| --- | --- | --- |
| 服务端 | Go 1.25+、Gin、gRPC | Web 接口 Gin + JSON；Agent 通信 gRPC 双向流 |
| 前端 | Vue 3.5 + Composition API + Pinia + Vue Router 4 + Vite 5 + ECharts 5 + Arco Design Vue | 兼容 Node 22 / 24 |
| Agent 主体 | Go 静态编译（`CGO_ENABLED=0`） | 跨平台单二进制 |
| Windows 采集组件 | C# .NET 8 + NativeAOT | 独立 exe，WMI 读取，目标机无需 .NET 运行时 |
| 通信协议 | Protobuf 3 + gRPC + TLS | Agent 双向流；前端 REST JSON + WebSocket |
| 元数据存储 | SQLite（默认）/ MySQL / PostgreSQL / GBase 8s | 适配器接口统一 |
| 时序存储 | 内嵌轻量 TSDB（默认）/ Prometheus / VictoriaMetrics / InfluxDB 2.x | 同上 |
| 部署形态 | 飞牛 FPK 原生应用 | Agent 独立分发 |

### 分层规则

1. **双协议隔离**：Web 前端走 REST JSON + WebSocket；Agent 走 gRPC 双向流 + Token 鉴权。**共用同一个监听端口**（见 [关键决策 D22](02-关键决策.md)），按 `Content-Type` 分流。
2. **业务层无状态**：不直接操作存储，全部经由适配器接口。
3. **存储可插拔**：换后端只改配置，业务代码零改动。
4. **引擎层独立**：路由计算、调度、告警匹配、闭环控制是纯逻辑组件，与接入层、存储层解耦，可单独测试。

## 5. Agent 目录（`agent/`）

```
agent/
├── cmd/{linux,windows}/main.go     平台入口（带 build tag）
├── internal/
│   ├── collector/                  common.go · linux_collector.go · windows_collector.go
│   ├── grpc/                       stream_client.go · report.go · command.go
│   ├── mesh/                       forward.go · topology.go · route.go
│   ├── bmc/ipmi_control.go         风扇调速 / 电源控制 / 指示灯
│   ├── cache/bbolt_cache.go        断网缓存队列，重连续传
│   ├── config/                     本地配置 + 服务端下发热加载
│   └── service/                    systemd_linux.go · windows_service.go
├── csharp_collector/               HardwareCollector.csproj（.NET 8 NativeAOT）· Program.cs
└── proto/                          proto 同步
```

- **Go 主进程统一管控**：通信、调度、转发、缓存、服务注册全部 Go 实现，跨平台复用。
- **Windows 采集组件化**：C# NativeAOT 编译为独立 exe，经 `go:embed` 嵌入 Go 二进制，运行时释放到临时目录执行。
- **Mesh 转发**：Agent 同时是 gRPC 客户端与中继服务端，按路由表转发，`hop_count` + `path` 防环路。
- **断网续传**：采集数据写入本地 bbolt 队列，重连后批量补传，靠 `batch_id` 服务端去重。

## 7. 部署形态

服务端封装为飞牛 FPK 原生应用（**单进程，无容器运行时**）。详见 [`04-部署/01-FPK打包与真机验证.md`](../04-部署/01-FPK打包与真机验证.md)。

> **纠正两处常见规格错误**（详见 [关键决策 D23 / D24](02-关键决策.md)）：
> 飞牛清单文件是**无扩展名的 INI 文件 `manifest`**，不是 `manifest.yml`；
> 前端 `engines` 不能写 `">=22 <=24"`（会把 Node 24.0.1+ 排除在外）。
