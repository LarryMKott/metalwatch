## 6. 已知缺口与风险（必须记住）

| 级别 | 事项 |
| --- | --- |
| 🟠 高 | FPK **未上真机**：静态二进制能否运行、package 用户写权限、重装数据恢复三项仍未验证（本机无 fnOS；WSL 被沙箱拦截，只能以 Windows 产物跑同一套代码路径冒烟） |
| 🟠 高 | **服务端未接线 WebUI 静态资源**：后端没有任何 `go:embed` 前端产物、也没有静态路由，`NoRoute` 直接返回 404 JSON；而 FPK 的桌面入口是指向 `:18080/` 的 iframe —— **当前装完包看不到界面**。CI 已把 `frontend/dist` 打进 FPK 的 WebUI 压缩包，但服务端还没有消费者。注意 `go:embed` 要求编译时目录已存在，会牵连 `go test ./...` 的构建顺序，属 D 级决策，需专门一轮 |
| 🟠 高 | **fnpack 本机仍未安装**：本地出包需先装（`build_fpk.py` 会明确告知跳过）；CI 发布链路已自动下载并出包（`--require-fnpack` 缺则失败） |
| 🟠 高 | 飞牛真机三项未验证：静态二进制能否运行、`package` 用户写权限、重装数据恢复（本机无 fnOS） |
| 🟠 高 | **ARM 包未上真机**：CI 已能自动出 `platform=arm` 的包，但没在 ARM 飞牛设备上装过 |
| 🟠 高 | Windows 采集依赖 C# NativeAOT 组件，本机无 .NET SDK，无法编译验证（CI 也只出 Go 侧 Agent） |
| 🟠 高 | 初始管理员口令会打进启动日志并写入 `bootstrap_admin.txt`（0600）—— 部署后必须提醒用户改密并删除该文件 |
| 🟡 中 | `deploy/` 未纳入 ruff：尚有 21 条（多为 `BLE001` 盲兜底异常），清干净再扩 CI 的 lint 范围，不要用 `--select` 制造假绿 |
| 🟡 中 | workflow 文件本身的校验（YAML 解析 / matrix 键覆盖 / artifact 名交叉比对 / `run` 块 `bash -n`）目前是仓库外的一次性脚本，未入库；本轮靠它抓出了 `release.yml` 7 处漏写 `#` 的解析错误 |
