## 3. 关键路径

```
W1a 元数据 ──┬─> W1b 分层 ──> W1c 时序 ──┬─> W4 IPMI 采集 ─┐
             └─> W2 资产 ────────────────┴─> W7 告警 ──────┼─> W8 前端 ──> W12 打包验证
proto 契约 ────> W3 gRPC ──> W6 Agent 客户端 ──> W5 采集 ───┘
```

**关键路径 = W1a → W1b → W1c → W4/W7 → W8 → W12。**

打包链路（W12）必须在 Phase 1 结束前**至少跑通一次**，不要留到最后——FPK 校验涉及
manifest 格式、换行符、端口一致性，失败点很隐蔽（见 `05-记录/01-实测记录.md`）。

## 4. 里程碑门禁

| 门禁 | 判据 |
| --- | --- |
| **G1** 契约冻结 | proto 三件套定稿并生成；字段只增不删 |
| **G2** 数据链路打通 | Agent 注册 → 上报 → 落库 → 查询出图，端到端跑通 |
| **G3** 可安装 | FPK 真机安装、启动、WebUI 可打开 |
| **G4** 可管控 | BMC 指令下发并生效，操作有审计 |
| **G5** 可规模 | 300 节点压测通过，Mesh 转发实测成功 |

## 5. 并行策略

- **单人推进**：严格按关键路径 `W1b → W1c → W4 → W7 → W8 → W12`，每个门禁自测后再进下一项。
- **两人协作**：
  - A：后端 `W1b/W1c → W3 → W4/W7`
  - B：前端 `W8` + Agent `W5/W6`
  - **交叉点**：proto 契约（G1）必须先冻结，否则两侧各写各的。

## 6. 风险登记册

| # | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| R1 | 飞牛 manifest 只声明一个 service_port | Agent 无法走独立端口 | 单端口按 Content-Type 分流（D22） |
| R2 | 飞牛只支持 `platform=x86` 或 `arm` 之一 | 需分别出包 | 校验脚本断言；CI 双架构构建 |
| R3 | C# NativeAOT 组件本机无法编译 | Windows 采集不可用 | 交付源码 + 构建命令，出包时编译 |
| R4 | 内嵌 TSDB 容量失控 | 磁盘占满 | 分块压缩 + 双档保留 + 容量告警 |
| R5 | IPMI 品牌差异大 | 采集项缺失 | 先覆盖 2 个主流品牌，其余按能力探测降级 |
| R6 | 静态二进制在飞牛真机跑不起来 | 整体不可用 | 打包链路提前验证（V1） |
| R7 | Mesh 中继放大流量 | 网络拥塞 | `max_hops` 上限 + 优先级分级 |
| R8 | 管理接口无鉴权 | 安全风险 | W11 必须完成；内网使用也要加 Token |
| R9 | `git rm -r` / 分支切换误删文件 | 代码丢失 | 禁用；操作前整包备份 |
