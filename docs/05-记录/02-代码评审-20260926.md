**M-3　`internal/service/host.go:114-127` + `internal/engine/alarm_engine.go:207-208` — 删除主机不做告警侧收尾，去重键用 hostname（存量）**

## 四、复核与纠错

按流程，子代理返回的每条 H/M 均已回读源码验证。**以下 3 条结论被收窄或改判，后续请勿按原结论动手**：

1. **「`run_tests.py` 复用旧 JUnit → CI 假绿」被收窄**（原报告称「CI/本地假绿」）。
   复核：CI 每次全新 checkout，`tests/python/reports/` 已被 `.gitignore:79` 忽略、不在版本控制 → 首次运行 `junit.exists()` 为 False → 抛 `RuntimeError` → job 红。**CI 门禁有效，该缺陷只影响本地重复执行**。降级理由见 M-14。

2. **「`adminOnly` 死条目是安全隐患」被改判为 L**。
   复核：`/users` 与 `/assets/export` 确实无路由注册（grep 全 `backend/` 仅命中该表），但**多出不存在的高危路由不会产生任何放行**——默认路径仍是「非 GET 需 operator+、走不到的表项不生效」。它反映的是功能未实现与表路由脱节，属可维护性。

3. **「`pkg/env` 的 TRIM_PKGVAR 兜底是 bug」被改判为设计取舍**（M-11）。
   复核：该兜底对**服务端**（跑在飞牛上，`TRIM_PKGVAR` 必存在）是正确且必要的；问题只出在 Agent 复用了同一判定，而 Agent 跑在无该变量的普通主机上。故保留 M 但改述为「Agent 侧 fail-open」，修复动作也是 Agent 侧告警而非改 env 判定。

此外，两条**子代理标注 L、经复核确认成立但值得提级注意**的：`conftest.py:23` 的 `F821` 确认是真 bug（写死的错名，非 `import` 误报）；`alerting.go:401` 确认与本次 diff 修的 `Evaluate` 是同一类缺陷、且是**本次改动的遗漏面**（诊断依据见 M-1）。

## 六、总体评价与修复优先级

整体方向是对的：把「环境差异」从散落的脚本与环境变量收口到一处判定，并把开发默认值做成显式的、可打印的、生产不生效的路径，这个设计比原先「每个脚本各读各的」清晰得多。跨 module 复用 `pkg/env` 也避免了语义漂移。

主要问题集中在两类：

1. **提交前的机械性阻塞**（H-1 格式、H-2 忽略规则）——这两条不修，CI 会红、口令会进仓库，与代码质量无关但后果确定；
2. **本次改造的覆盖面不全**——`agent_offline` 告警漏了 id 回填（M-1）、`start-agent.ps1` 仍注入 `host_id=1` 覆盖新逻辑（M-16）、两个平台 main 写盘失败仍报成功（M-12）。都是「改了一半」的形态。

建议顺序（安全 > 数据一致性 > 可追溯性 > 卫生）：

| 批次 | 内容 | 理由 |
| --- | --- | --- |
| 1 | H-1、H-2 | 不修则 CI 红 / 凭据入库 |
