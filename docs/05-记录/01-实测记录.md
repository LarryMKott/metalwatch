### 8.3 过程中修掉的真 bug

1. **pipeline 停机丢点**：`Stop` 后的最终 flush 复用了已取消的 context，`BeginTx` 直接失败且错误被吞 —— 改为写入固定用独立 context。

3. **RAID 模板语义**：单 op 模板下 `ne` 对 crit 不成立，改为 `eq 1→major / eq 2→critical`（重建中不告警，进度走 `raid_rebuild_percent`）。

### 10.3 设计说明

- **上行时间轴**：流消息的 `timestamp` 为采集时刻（Unix ms），超 24h 补传窗口拒收——与 JSON 通道口径一致，为 W6 断网续传铺路。
- **下行命令通道**：`StreamServer.SendCommand(hostID, cmd)` 按主机注册下行 sink（断开即清理），W15 BMC 指令下发将直接复用；缓冲满返回 ResourceExhausted 而非阻塞。
- **优雅停机**：HTTP Shutdown → gRPC GracefulStop（GOAWAY，5s 超时硬停）。

### 11.3 过程中发现并修复的问题

1. **明文监听不认 HTTP/2**：Go 的 net/http 默认只支持 TLS 上的 h2，gRPC 明文建连的

2. **中文 Windows 的 PowerShell 输出编码**：默认 GBK 系编码产生非 UTF-8 字节，

3. `--server` 默认值从 `https://127.0.0.1:18080` 改为 `http://`（服务端当前明文监听，
   原 https 默认值必然连接失败；TLS 由部署层提供时再改回）。

### 14.3 过程中发现并修复的问题

1. **`pkg/crypto` 包名不一致**：`crypto_test.go` 声明 `package crypto`，与新写的 `package cryptox` 冲突，`go vet ./...` 直接报 found packages。统一为 `crypto`。
2. **依赖环**：`handler` 需要读请求主体，但 `api/web`（中间件所在）已 import `handler`，不能反向引用 → 抽出 `internal/authz` 包。
3. **`created_at` 漏写**：`app_user/api_token/audit_log` 的迁移 DDL **不带 DEFAULT**（跨方言约定：时间戳由应用层写），三处 INSERT 未写该列 → `NOT NULL constraint failed`。已补。
4. **`ttl <= 0` 一律折算成默认值**：导致无法签发「已过期」令牌，测试覆盖不到过期分支。改为仅 `ttl == 0` 取默认，负值表示立即过期。
5. **测试环境无主密钥就不鉴权**：原本写成 `if d.MasterKey != nil` 才挂中间件 —— 生产误配置时会静默裸奔。改为无条件挂载。

### 14.4 说明与边界

- **会话无状态**：服务端不维护会话表，登出即客户端丢弃令牌。单机 FPK 场景够用；若要「强制下线」需再引入黑名单表。
- **登录守卫不持久化**：失败计数在进程内存，重启清零；跨实例部署需换成存储层计数。
- **权限判定在中间件**：写操作一律要求 operator+，高危路径（用户/Token/BMC 凭据/主机增删/明文导出）要求 admin。新增接口默认受保护，但**新路径若属高危需手动加入 `adminOnly` 表**。
- **初始口令进日志**：首次启动会把随机口令打到启动日志（WARN）并写入 `bootstrap_admin.txt`（0600）。这是为了让用户拿得到；确认后应删除该文件。
- 前端令牌存 localStorage（XSS 可读），取舍理由：无富文本渲染入口 + 12h 过期，比每次刷新都要重登录更划算。
