### ⚠️ 踩坑记录：Vite 8 的 `manualChunks` 只接受函数

初次构建两个 Node 版本**同时失败**：

```
Warning: Invalid output options (1 issue found)
- For the "manualChunks". Invalid type: Expected Function but received Object.
✗ Build failed in 108ms
error during build: TypeError: manualChunks is not a function
  at .../rolldown/dist/shared/create-bundler-option-*.mjs
```

原因：Vite 8 默认使用 **rolldown** 打包，`manualChunks` 的对象写法不再支持。
已改为函数形式（在 rollup 与 rolldown 下都有效），并把这条坑写进 `vite.config.ts` 注释。

## 4. Agent 三平台编译

```
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build ./...   → OK
CGO_ENABLED=0 GOOS=linux   GOARCH=amd64 go build ./...   → OK
CGO_ENABLED=0 GOOS=linux   GOARCH=arm64 go build ./...   → OK
go vet ./...                                             → 通过
```

踩坑：`add()` 采集辅助函数最初写在 `linux.go`（带 `//go:build linux`），导致 Windows 构建报
`undefined: add`。已移到无 build tag 的 `util.go` —— **平台文件里只放平台相关实现**。

### 7.1 发现并修复的真实缺陷（比"清理"本身更重要）

| # | 缺陷 | 影响 | 修复 |
| --- | --- | --- | --- |
| 1 | Agent 上报的 `agent_version` **恒为 "dev"**：`collect.SetVersion` 从未被调用，main 里的版本常量没有下发 | 服务端看到的 Agent 版本永远是 dev，无法做版本收敛与升级提示 | 两个入口显式调用 `collect.SetVersion(version)` |
| 2 | Agent 心跳的 `host_id` **恒为 0**：`heartbeat.New` 不接收 hostID，`SetHostID` 无人调用 | 服务端 `host_id` 与令牌不匹配会直接 **403**，心跳功能实际不可用 | 改为构造参数化 `heartbeat.New(sender, hostID, interval)`，导出 `report.HostIDFromEnv` 复用 |
| 3 | `.gitignore` 的 `.env.*` 把 `frontend/.env.development`、`.env.production` 一并忽略 | clone 后不知道构建期需要哪些变量 | 改为只忽略 `.env.local` / `.env.*.local` |
| 4 | npm 自动补装的 `@types/node@^26.6.2` **比运行时（Node 22/24）还新** | 类型允许写出运行时不存在的 API，编译期发现不了 | 固定为 `^22.19.0`（与 engines 下限一致），并在 tsconfig 的 `types` 中显式声明 |
